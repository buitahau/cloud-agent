# MVP Prerequisites — what to prepare before starting

Checklist for the person running the [MVP plan](README.md). Everything here is needed **before or during tasks 00–03**. Tick items as you go; items marked 🛑 can stop the project if the answer is bad.

## 0. Decisions to make first (5 minutes, no tools)

| # | Decision | Why / used by |
|---|---|---|
| D1 | **Which repo is the target?** One repo with a Playwright E2E suite. Note its GitHub `owner/name`. | Everything. The MVP supports one project. |
| D2 | 🛑 **A3: do the E2E tests hit what dev already serves, or must the branch be deployed to dev first?** Write the answer down. | Task 00. If "deploy first", the MVP still works but the demo only covers test-code changes. |
| D3 | **Which Claude model to pin** (e.g. a Sonnet/Opus model id) | `MODEL` in config; keeps runs comparable. |
| D4 | **Which auth method for Claude on the VPS**: interactive login or `claude setup-token`. Default: try login first, compare in task 03. | Task 03. Fallback if neither works unattended: an API key (billed per token). |
| D5 | **Project name** (short slug, e.g. `myapp`) | `PROJECT` config key, `cloudtest run <project>`. |

## 1. VPS

- [ ] A Linux VPS (Ubuntu 22.04/24.04 LTS or Debian 12 recommended) with **root/sudo** access.
- [ ] Size: **≥ 4 vCPU, ≥ 8 GB RAM, ≥ 20 GB free disk** (Chromium + suite). Smaller works but may be flaky; task 01 measures it.
- [ ] Outbound internet: GitHub, npm registry, NodeSource, Playwright browser CDN, Anthropic API, Tailscale.
- [ ] SSH access for yourself as a sudo user.
- [ ] 🛑 **The VPS can reach the dev environment** (task 00 checks this with `curl`).
  - [ ] Note the VPS **public IP**.
  - [ ] If dev is behind an IP allow-list or VPN: someone who can add the VPS IP (or install a VPN client) is identified. Record the owner.
  - [ ] Know **every host** the suite calls (app URL, login/API host, any third-party hosts the tests need).
- [ ] Do not reboot the VPS in the ~26 h after task 03 step 11 (the soak timer is transient).

## 2. Accounts and credentials

| Item | What | Where it ends up |
|---|---|---|
| **Claude subscription** | A Pro/Max login you can use interactively on the VPS (browser/device login step), **personal use only** (see architecture §7 terms note). Optional: ability to run `claude setup-token`. | `~cloudtest/.claude/.credentials.json` or `/etc/cloudtest/claude-token` |
| **GitHub fine-grained PAT** | Repository access: **only the target repo**. Permission: **Contents: read-only**. Set a sensible expiry and note it. | `/etc/cloudtest/github-token` (task 02) |
| **Tailscale account** | A tailnet you control; ability to join the VPS and laptop. (Or accept the `ssh -L` fallback.) | VPS + laptop |
| **Test-only dev credentials** | Dedicated test account(s) for the dev environment (not your personal login). | `/etc/cloudtest/project.env` |
| **API token** | Generated by you in task 08 (`openssl rand -hex 32`). Nothing to prepare. | VPS + `~/.config/cloudtest/token` |

Never reuse an `ANTHROPIC_API_KEY` on the VPS: it overrides the subscription login. Make sure it is unset there.

## 3. Information about the target repo (collect now)

- [ ] **Playwright version** in the repo (task 01 installs matching system deps).
- [ ] **Node version** the repo expects (the plan installs Node 22 LTS; flag any mismatch).
- [ ] **Env vars the suite needs**: base URL, test-account credentials, anything else (copy names from `.env.e2e`/CI config). List them in a scratch file for task 02.
- [ ] **How the suite runs locally** (`npx playwright test`? extra args?). Task 04 will add an `e2e:ci` npm script: `playwright test --reporter=list,json`.
- [ ] A **laptop run result** on a known commit (pass/fail counts, duration) to compare against the VPS baseline in task 02. Run it with `CI=1` ([task 00b](tasks/00b-local-smoke.md) produces exactly this).
- [ ] Playwright config: confirm `screenshot: 'only-on-failure'` (or `'on'`) and default `test-results/` output dir. If not, you will need to change it in the repo (task 04).
- [ ] You can **commit to the repo** (tasks 04 and 10 add `CLAUDE.md` instructions and the `e2e:ci` script) and **force-push the branch `agent/test`** (the CLI does `git push -f origin HEAD:agent/test`). Check branch protection does not block that name. Use a dedicated branch name if several machines push.
- [ ] The suite is **safe to run concurrently with your own manual use of dev** (shared dev data). Test accounts and one run at a time are the mitigation.

## 4. Laptop

- [ ] **Node 22** (the CLI is plain Node, no npm packages).
- [ ] `git`, `ssh`, `curl`, **`jq`**.
- [ ] **Tailscale** installed and logged in to the same tailnet.
- [ ] **Claude Code**, a pinned version, plus permission to add `Bash(cloudtest:*)` to the target repo's `.claude/settings.local.json`.
- [ ] Push access to the target repo (SSH key or credential helper) for the `agent/test` branch.
- [ ] An SSH key you can add to `~cloudtest/.ssh/authorized_keys` on the VPS (or use Tailscale SSH).
- [ ] A place for the token file: `~/.config/cloudtest/token` (mode `0600`).

## 5. Time and people

| Item | Estimate |
|---|---|
| Working time | **7–8 working days** (README §7), plus 2–3 mostly passive days for the auth soak |
| Who can answer A3 / dev allow-listing | Identify them now so you are not blocked on day 1 |
| Quiet window on dev for drills | Task 11 runs red/green/timeout drills and 5 consecutive runs |

## 6. Suggested order for the first hour

1. Make decisions D1–D5 and write the A3 answer (task 00 step 1). If the VPS is not ready yet, do [task 00b](tasks/00b-local-smoke.md) (laptop smoke test) first.
2. Get the VPS and its public IP; run the two `curl` checks from it (task 00 step 2). **Stop here if dev is unreachable and cannot be allow-listed.**
3. Create the GitHub PAT and the Tailscale account/auth key; collect the repo details in §3.
4. Start [task 01](tasks/01-vps-provisioning.md).

## 7. Things the plan does *not* need (don't spend time on them)

Domain name, TLS certificate, Cloudflare, Docker, a database, a dashboard, Redis, multi-user accounts, an Anthropic API key (unless task 03 fails both subscription methods).

## 8. Known accepted risks to be aware of

- Test code and `npm ci` run as the `cloudtest` user, which can read `/etc/cloudtest/*` and the Claude credentials (README R2). Mitigations: own repo, read-only single-repo PAT, tailnet-only API. A separate run user is a post-MVP fix.
- Every run consumes your Claude subscription limits; task 03 records usage per run.
- If anyone other than you triggers runs, the subscription terms change: switch to an API key.
